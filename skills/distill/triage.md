# Triage

Move issues through a small state machine so the backlog says, for every issue, exactly what happens next.

Every comment posted to the tracker during triage **must** start with:

```
> *This was generated by AI during triage.*
```

## States and Categories

Each triaged issue carries exactly **one category** and **one state** label:

| Kind | Values |
|------|--------|
| Category | `bug`, `enhancement` — via **issue type** (`Bug`, `Feature`) when the org has issue types configured, via label otherwise; never both |
| State | `needs-triage`, `needs-info`, `ready-for-agent`, `ready-for-human`, `wontfix` — always labels |

- `needs-triage` — awaiting evaluation (the default entry state)
- `needs-info` — waiting on the reporter; returns to `needs-triage` when they reply
- `ready-for-agent` — fully specified; an agent can pick it up cold
- `ready-for-human` — needs human judgment, external access, or manual testing
- `wontfix` — will not be actioned (close it)

Check `gh label list --limit 1000` first; map to existing label names where the repo already has equivalents, and create missing ones (with color and description) rather than duplicating. Conflicting state labels on one issue: flag and ask before touching anything.

## Invocation

The user describes what they want in natural language — interpret and act:

- "What needs my attention?" → present three buckets, oldest first: **unlabeled**, **needs-triage**, **needs-info with reporter activity since last triage notes**. Counts plus a one-line summary each; let the user pick.
- "Look at #42" → full triage (below)
- "Move #42 to ready-for-agent" → trust them: confirm the actions (labels, comment, close), apply, skip the analysis. Ask whether they want an agent brief written.

## Triaging an Issue

1. **Gather.** Read the issue fully (body, comments, labels, dates); parse prior triage notes so nothing is re-asked. Check the codebase for **redundancy** — search for an existing implementation by domain concept, not the request's wording, and report where you looked. Already built → `wontfix`, pointing to where it lives.
2. **Recommend.** Category + state with reasoning and a brief codebase summary. Wait for direction.
3. **Verify.** For a bug, reproduce from the reporter's steps before anything else. Confirmed (with code path), failed, or insufficient detail — the last is a strong `needs-info` signal.
4. **Elicit if thin.** A request that needs fleshing out gets frontier rounds (`elicit.md`) — with the *user/maintainer*, not by inventing answers on the reporter's behalf.
5. **Apply:**
   - `ready-for-agent` → post an agent brief (below)
   - `ready-for-human` → same brief, plus why it can't be delegated
   - `needs-info` → post triage notes (below)
   - `wontfix` → close with a polite comment: where it already exists, or why it's rejected
   - Always end with exactly one category (type or label) + one state label

## Agent Brief

A comment that lets a fresh agent start cold:

```md
> *This was generated by AI during triage.*

## Agent brief

**Goal:** [the end-to-end behavior to deliver]
**Verified:** [repro/claim check result, with code path]
**Where to look:** [domain concepts and entry points — not exhaustive file lists]
**Acceptance criteria:**
- [ ] …
**Out of scope:** [boundaries]
```

## Needs-info Notes

```md
> *This was generated by AI during triage.*

## Triage notes

**Established so far:**
- …

**Still needed from you (@reporter):**
- [specific, answerable questions — never "please provide more info"]
```

Capture everything settled so far under "established" — the next triage session resumes from it instead of re-asking.
